# 모션 스무딩 — Gaussian → One-Euro (속도 적응형) 전환

## 증상
빠르고 날카로운 소스 모션(펀치, 빠른 댄스 동작, 급정지)이 내보낸 애니메이션에서
**지나치게 부드럽고 둥둥 뜨는 느낌**으로 출력되었다. 느린 연기는 문제가 없었으며,
모션이 공격적일수록 "수중 촬영"처럼 느껴지는 현상이 심해졌다.

## 원인 분석
후처리 단계(`scripts/pt_to_anim.py`)에서 모든 관절에 대해
**균일한 시간 가우시안(uniform temporal gaussian)**으로 스무딩을 적용하고 있었다:

```
sigma = motion_smoothing * 5.0          # UI 0.55 -> sigma = 2.75 프레임
radius = 3 * sigma ≈ 8                  # -> 17-프레임 합성곱 윈도우
```

30 fps 기준으로 각 포즈를 **약 0.57초** 범위의 인접 프레임들과 평균화하는 것이다.
실제 작업 로그(`data/jobs/<id>/logs/3_pose.log`)에서 확인된 증거:

```
[pt_to_anim] smoothing: gaussian sigma=2.75 frames (all 55 joints)
```

가우시안은 고정된 저역 통과 필터이므로, 고주파 성분이 **지터인지 의도된 모션인지 구분 없이** 감쇠시킨다. 날카로운 모션의 사실감은 정확히 그 고주파 성분(충격 시점의 속도 피크, 즉각적인 방향 전환)에 존재하기 때문에, 펀치의 속도 스파이크가 ±0.28초의 준비/복귀 동작과 함께 평균화되어 부드러운 밀기 동작으로 변질되었다. 이 필터는 추적 노이즈와 빠른 사지 움직임을 구별할 수 없으며, 바로 그 *불가능함*이 버그의 본질이다.

보조 원인 후보 배제: `fallback_pose` 디스파이커(45°/프레임 임계치)가 합법적으로 빠른 프레임을 제거할 *수도* 있었지만, 작업 로그에서 한 번도 발동되지 않은 것을 확인하였다 — 가우시안 단독으로 증상이 설명된다.

## 수정 — One-Euro 필터 (Casiez et al., CHI 2012)
`pt_to_anim.py`에서 균일 가우시안을 **속도 적응형** 저역 통과 필터로 교체하였다
(동일한 6D 회전 표현, 동일한 호출 지점):

- **느린 신호** → 컷오프가 `min_cutoff`에 유지 → 지터를 강하게 제거한다.
- **빠른 신호** → 컷오프가 속도에 비례하여 상승
  (`cutoff = min_cutoff + beta * |velocity|`) → 날카로운 모션이 거의 그대로 통과한다.
- **제로 위상 지연(Zero phase lag)**: One-Euro는 인과적(causal) 필터이므로(실시간 입력용으로 설계됨) 단일 패스 적용 시 애니메이션이 지연된다. 오프라인 데이터를 처리하므로 순방향 패스와 역방향 패스를 실행한 후 평균을 취한다 — 지연이 정확히 상쇄된다.

기존 `motion_smoothing` UI 슬라이더(0~1)는 유지되며, 로그 스케일로 `min_cutoff`에 매핑된다:

| 슬라이더 | min_cutoff | 특성 |
|----------|------------|------|
| 0.1 | 6.3 Hz | 신호를 거의 건드리지 않는다 |
| 0.55 | 0.8 Hz | 정지 시 강한 지터 제거 |
| 1.0 | 0.1 Hz | 매우 강한 스무딩 |

고정 상수: `ONE_EURO_BETA = 1.5` (단위 속도당 컷오프 증가율 — 6D 회전 단위와 미터 모두 O(1) 크기), `ONE_EURO_DCUT = 1.0 Hz` (속도 추정값 자체에 대한 저역 통과).

## 검증
필터 수학의 순수 Python 재현으로, 문제가 발생한 작업과 동일한 강도(`motion_smoothing = 0.55`)에서 테스트하였다:

| 신호 | Raw | One-Euro | 기존 Gaussian |
|------|-----|----------|---------------|
| 정적 포즈 지터 (RMS) | 0.0056 | **0.0020** (−64%) | 0.0022 |
| 펀치 최대 속도 | 15.0 | **11.3 (75% 보존)** | 4.2 (28% 보존) |
| 스텝 응답 지연 | — | **0 프레임** | 0 (대칭 커널) |

이전과 동일한 수준의 지터 억제를 달성하면서, 가우시안이 파괴한 날카로움(−72%)이 이제 보존된다(−25%). 새로운 작업 로그:

```
[pt_to_anim] smoothing: one-euro min_cutoff=0.79 Hz, beta=1.5 (all 55 joints, zero-phase)
```

## 튜닝 가이드
- 매우 빠른 테이크에서 결과가 여전히 부드럽다면 → `ONE_EURO_BETA`를 올린다 (속도 민감도 증가) 또는 슬라이더를 낮춘다.
- 느린 정지 동작에서 잔여 지터가 보인다면 → 슬라이더를 올린다 (`min_cutoff`가 낮아짐). 설계상 빠른 모션에는 영향을 주지 않는다.
- 소스 측 대응: 가능하다면 **60 fps**로 촬영한다 — 30 fps에서는 빠른 사지가 *입력* 프레임에서 이미 모션 블러로 흐려지므로, 후처리 이전에 GVHMR의 추정 자체가 이미 부드러워진 상태이다.

## 수정된 파일
| 파일 | 변경 내용 |
|------|-----------|
| `scripts/pt_to_anim.py` | 가우시안 커널 → One-Euro (순방향+역방향, 제로 위상), 로그 출력 변경 |
| `scripts/pipeline_config.py` | `motion_smoothing` 문서 주석 업데이트 |
| `frontend/components/OptionsPanel.js` | 슬라이더 힌트: 빠른 동작 자동 보존 안내 추가 |

Docker 재빌드는 필요하지 않다 — `scripts/`는 GVHMR 컨테이너에 볼륨 마운트되어 있다.
